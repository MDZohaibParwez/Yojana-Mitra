# Security & privacy

## Data we never collect

Aadhaar, PAN, bank account / IFSC, card numbers, voter ID, OTPs, PINs, passwords. Every channel runs
`assertNoSensitive` / `findSensitive` (`packages/core/src/privacy.ts`: Verhoeff check for Aadhaar, Luhn
for cards, PAN / IFSC / voter-ID patterns, OTP / password keywords) **before** anything is processed or stored:

| Channel | Behaviour on sensitive input |
|---|---|
| MCP / REST | `sensitive_data` error (HTTP 422 / MCP `isError`), nothing stored |
| WhatsApp / web chat | Friendly warning in the user's language; the message is dropped, the session is not updated |
| `report_issue` | Rejected; accepted reports are additionally redacted (phones, emails, long numbers) |

The `Profile` schema is `.strict()` and contains no identifier fields; unknown keys are rejected.

## Storage

| Table | Contains personal data? |
|---|---|
| `usage_events` | No — channel, tool, state, lang, timestamp only (enforced by a test that checks the columns) |
| `scheme_views` | No — per-scheme daily counters |
| `chat_sessions` | Short-lived profile answers keyed by `HMAC-SHA256(SESSION_HMAC_KEY, wa_id)`; expires after `SESSION_TTL_MINUTES` (60), purged daily by cron |
| `reports` | Redacted free text |
| `admin_api_keys` | sha256 of keys only |

Logs never include request bodies or phone numbers (error logs print only error names; long digit runs are masked).

## Transport & HTTP hardening

- HTTPS only (HSTS preload headers on all apps). Importers refuse non-HTTPS URLs.
- Secure headers: CSP (`default-src 'none'` on the APIs, restrictive policy on the website), `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`.
- Body size limits: 64 KB (API), 128 KB (MCP), 256 KB (WhatsApp webhook).
- Rate limits: per anonymous client key (`sha256(ip + day + secret)`), per WhatsApp session, per admin token. Put a Vercel Firewall rate-limit rule in front for a global hard cap.
- Input validation with zod on every tool, admin route and server action. SQL only through Drizzle / parameterised `sql` templates.

## WhatsApp webhook

- `X-Hub-Signature-256` verified with the app secret using `timingSafeEqual` on the **raw** body; unsigned requests get 401.
- Verify-token handshake for subscription.
- Duplicate deliveries are ignored (message-id ring buffer in session state).
- Media is downloaded only from Meta hosts (`fbsbx.com`, `facebook.com`, `fbcdn.net`, `whatsapp.net`) so the access token cannot leak; max 16 MB; audio is processed in memory only.

## Admin API

- API keys (`ym_…`, 256-bit random) stored as sha256; constant-time comparison for env keys; revocable DB keys; scopes `read / write / review`.
- Optional HS256 JWT (15 minutes, `iss` checked, algorithm pinned).
- Any edit returns content to `pending` unless explicitly approved by a `review`-scoped principal.
- Vercel Cron endpoint authenticated with `CRON_SECRET`.

## Content integrity

- Nothing generated by an LLM (rules, translations) or imported is shown before human approval; a DB CHECK constraint enforces that approved rules record who approved them.
- Every answer carries the official source URL and `last_verified_at`.
- Monthly re-verification hides schemes whose links break or whose source page changes.

## Secrets

Only in environment variables (see `.env.example`); `.env*` is git-ignored. Required in production:
`DATABASE_URL`, `SESSION_HMAC_KEY`, `WHATSAPP_*`, `ADMIN_API_KEY_HASHES` (or DB keys), `ADMIN_JWT_SECRET`, `CRON_SECRET`;
optional `ANTHROPIC_API_KEY` (ingestion only), `STT_API_KEY`, `EMBEDDINGS_*`.

## Dependencies

`pnpm audit --prod` reports no known vulnerabilities at the time of this build (zod ≥ 4.6.6, drizzle-orm ≥ 0.45.2,
@hono/node-server ≥ 2.1.3, postcss forced ≥ 8.5.23 via `pnpm.overrides`). CI runs typecheck, tests and build on every PR.

## Known limitations / follow-ups

- In-memory rate limiting is per serverless instance — add Vercel Firewall rules or Upstash for a global limit.
- The website CSP allows `'unsafe-inline'` scripts (needed by Next.js inline bootstrap); move to nonces via middleware if stricter CSP is required.
- Regional-language strings and curated scheme data need human review before launch (see DECISIONS.md).

## Reporting a vulnerability

Please open a private security advisory on the GitHub repository rather than a public issue.
